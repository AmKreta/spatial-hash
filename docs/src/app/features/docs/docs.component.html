A TINY GRID WITH A BIG JOB

Find what's nearby.
Skip the rest.

SpatialHash is a lightweight uniform grid for quickly finding objects near a point or inside a rectangle. It helps games, canvases, and maps avoid checking every object for every query.

01 — THE IDEA

Nearby objects, without the full scan.

Imagine a huge floor divided into square tiles. Each item is placed into every tile its rectangle touches. When you ask what overlaps a region, SpatialHash looks in the relevant tiles, then checks the real bounds of those few candidates.

CELL SIZE
One lookup. A small shortlist.

A naive scan checks every item (O(n) per query). A spatial grid usually checks only nearby candidates. Results are still confirmed against exact rectangle bounds.

✳

The trade-off: objects are stored in each cell they overlap, so larger objects occupy more cells. Choose a cell size close to the typical object or query size.

02 — INSTALL

Add it to your project.

npm install @amk-utils/spatialhash

Works in modern Node.js, bundlers, and browsers. Import the typed package where you need a broad-phase lookup.

03 — QUICK START

Index once. Query as you move.

import { SpatialHash } from '@amk-utils/spatialhash';

  type Sprite = { x: number; y: number; width: number; height: number; name: string };
  const world = new SpatialHash<Sprite>({ cellSize: 64 });

  world.add('player', { x: 10, y: 20, width: 32, height: 32, name: 'player' });
  world.add('coin', { x: 60, y: 40, width: 16, height: 16, name: 'coin' });

  const nearby = world.getItemsBetween(0, 0, 100, 100);
  world.update('player', { x: 50, y: 20, width: 32, height: 32, name: 'player' });

An item needs x, y, width, and height. Keep its ID stable while updating its bounds. IDs can be strings or numbers; 1 and '1' are distinct.

04 — API REFERENCE

Small API. Clear behavior.

new SpatialHash<T>(options?)

Creates an empty index. T must extend Bounds and can include any extra payload fields.

add(id, data): void

Adds the item to every grid cell its bounds overlap. Throws if that ID already exists.

remove(id): boolean

Removes the item and its cell memberships. Returns true if it existed; otherwise false.

update(id, data): void

Replaces the payload and bounds, removing old cell memberships and adding new ones as needed. Throws if the ID is missing. Call this when an item moves.

getItemsBetween(x, y, width, height): T[]

Returns payloads whose bounds overlap the rectangle. Touching edges do not count. Result order is undefined.

getItemsBetweenWithStats(x, y, width, height): SpatialHashQueryResult<T>

Returns the same matches plus the number of candidate item bounds compared. Useful for profiling or explaining how much work a query avoided.

size: number

Read-only count of stored items, including items whose bounds cover no cells.

clear(): void

Empties the index and releases all cell buckets.

Types you can import

Bounds

The required rectangle shape: numeric x, y, width, and height.

ItemId

A number or string identifier. Numeric and string forms remain distinct.

Hash

A number or string key returned by the hash function for a grid cell.

HashFunction

A callback that receives integer column and row coordinates and returns the bucket key.

SpatialHashOptions

The optional cellSize, threshold, and hashFunction constructor settings.

SpatialHashQueryResult<T>

The matched items and candidate bounds comparison count from an instrumented query.

SpatialItem<T>

The stored-item shape: ID, payload, and cell hashes. Queries return payloads, not wrappers.

05 — CONFIGURATION

Pick the grid that fits.

new SpatialHash({
    cellSize: 64,
    threshold: 1,
    hashFunction: (column, row) => String(column) + ',' + String(row),
  });
cellSize

World-space width and height of each square cell. Defaults to 100; must be greater than zero.

threshold

Extra lookup margin in cell units, on each side of a query. Defaults to 1. It broadens candidate collection only; exact overlap still uses the original query rectangle.

hashFunction(column, row)

Maps integer cell coordinates to a string or number key. Defaults to zigzag encoding followed by Cantor pairing, preserving distinct negative coordinates.

06 — UNDER THE HOOD

From rectangle to result.

  1. 01
    Cover the cells

    Coordinates are divided by cellSize and rounded down. The rectangle's far edge is inset by a tiny epsilon so an edge on a cell boundary doesn't spill into the next cell.

  2. 02
    Index every covered cell

    Each cell's integer column and row are hashed into a bucket. A set of IDs in each bucket avoids duplicates.

  3. 03
    Gather candidates

    Queries visit their covered cells, expanded by cellSize × threshold around every side, and merge IDs into a unique candidate set.

  4. 04
    Check exact bounds

    Candidates are filtered with strict rectangle overlap tests against the unexpanded query. Shared edges alone are excluded.

Internal helpers

getCellX and getCellY floor world coordinates into integer cell coordinates. getCells enumerates covered cells, returning an empty list for non-positive dimensions. hash calls the configured hash function. The default applies zigzag encoding to support negative coordinates, then Cantor pairing to combine the pair into one number.

addToCell creates a bucket when needed and adds an ID. removeFromCell deletes the ID and removes buckets that become empty. haveSameCell detects unchanged coverage so updates only edit grid membership when necessary.

Moving an item: update recalculates its covered cells. If coverage has not changed, it only replaces the payload. Otherwise it edits only the cells that changed.

Invalid dimensions: non-positive width or height covers no cells, so that item remains counted in size but won't appear in queries.

Validation: a cell size at or below zero and a negative threshold throw errors in the constructor.

Hash responsibility: custom hash functions should return a unique key for each cell coordinate in use. Colliding keys merge buckets and may affect correctness.
